# 微信支付接入准备

当前真实支付明确拒绝，MOCK 和 MOCK_WALLET 不能解释为真实收款。此设计未接通商户号、证书、真实回调或资金。

接入时新增 PaymentGateway 接口，create/query/refund/queryRefund 分离，通道实现使用商户配置。服务器从锁定的订单读取金额，不信任客户端金额。金额转换为整分并校验币种、商户号、appid、订单号；券及积分在同一订单事务内保留。外部调用必须设置连接与读取超时。

发起支付先持久化待处理记录与唯一商户单号，再提交事务，再调用渠道。外部超时返回“处理中”，通过查询确认，禁止直接认定失败并再次扣款。使用 outbox 或任务表重试，不在数据库长事务内等待支付网络。回调验签、解密、防重放，并以平台交易号和商户单号双重幂等；金额与币种不符则拒绝入账并报警。仅可信回调或主动查询能将订单置为已支付。

退款使用唯一退款单号，累计退款不超过实付；待确认退款保持 REFUNDING，成功后再释放对应权益。退款失败、重复回调、回调先于同步响应、已取消订单迟到支付，必须走显式补偿与人工处理队列。保留审计流水，禁止覆盖原支付和退款记录。对账按渠道账单、支付流水、订单和余额逐日比对；模拟通道始终单列。

待执行测试：签名错误/证书轮换/重复与乱序回调/金额不符/网络超时/支付成功但落库失败/超时关单与到账竞态/退款处理中重试/部分退款上限/日终差异。先用可控桩做协议测试，再用官方许可的测试环境，由用户确认后完成渠道验收；不使用顾客资金作为测试数据。
